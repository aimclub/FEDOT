# Категории TensorData: сохранение и optional imputation

9 ноября 2026. Подготовительная задача перед продолжением миграции бустингов.

## Контракт

- `categorical_features`: NumPy-массив исходных значений категорий, одна строка на sample.
  Может содержать строки и пропуски; числовое `features` остаётся Torch на выбранном устройстве.
- `categorical_source_idx`: исходный ID для каждого столбца этого массива. Не позиции OHE-столбцов.
  Значения сохраняются перед кодированием и после удаления строк с пропусками в target.
- `categorical_idx`/`numerical_idx`: текущие позиции столбцов `features`; `idx_mapping` связывает их с источниками.
- `get_not_encoded_data()` возвращает `CategoricalData`: текущий числовой тензор и активные исходные категории.
  Это простой тип из `contracts.py`, без `to_dataframe()` и pandas-зависимости. Формат библиотеки выбирает
  модельный адаптер; числовой тензор не переносится на CPU. Удалённые/спроецированные категории не возвращаются.
- На fit/predict используется одна обученная схема кодирования. Predict сохраняет свои категории,
  а не исходные строки обучающей выборки. Неизвестная категория отличается от пропуска.

## Imputation

- Создание TensorData не заполняет категориальные пропуски. Без optional imputation они сохраняются.
- При imputation модой выбирается категория по исходным значениям train. Заменяются и исходное значение,
  и весь выбранный кодированный блок. Шаблон берётся из обучающего тензора для этой категории, поэтому
  сохраняет уже выполненные преобразования. Статистика не переоценивается на predict.
- Константа тоже обновляет оба представления. Если значение не встречалось в train, сохранённый encoder
  кодирует его как неизвестную категорию: OHE — нули, label — обученный unknown ID. Словарь не расширяется.
  Для этого fitted snapshot хранит связь source ID с локальной колонкой энкодера.
  Метод энкодера `encode_imputation_value(column_idx, fill_value)` возвращает код категории,
  подставляемой вместо пропуска, по уже обученному словарю; сам пропуски в данных он не заполняет.
- Для совершенно пустого обучающего категориального столбца мода не выдумывается: пропуски остаются.
  OHE сохраняет один пустой столбец вместо полного исчезновения источника; константа остаётся возможной.
- Mean/median для исходных категорий не определены и отклоняются, как и выбор части OHE-блока для
  категориальной imputation. Для числовых признаков прежние методы не менялись.
- Новая константа после частичного удаления либо явного преобразования категориального кодированного блока
  требует отдельного контракта и сейчас отклоняется. Иначе, например, после explicit scaling можно было бы
  записать в масштабированные колонки обычные немасштабированные биты. Известная категория использует уже
  преобразованный train-шаблон. Произвольные custom-преобразования не имеют общего обратного преобразования;
  не подменять это молчаливым inverse encoding.
- Scaling по умолчанию работает только с числовыми столбцами и не меняет категории.
- Обработчик `CategoricalImputation` находится рядом с другими imputation в `methods/imputation.py`.
  NumPy используется для исходных строк и их частот; замена числовых OHE/label-блоков выполняется Torch
  на устройстве `features`. Пропуски уже приведены к np.nan на входной границе, как у текущих энкодеров.
  Pandas в новом runtime-коде не используется. Существующие чтение данных и определение категорий
  через `Backend().pd` в рамках этой правки не переписаны.

## Библиотечная подготовка

В `ModelImplementation` добавлен identity-hook `prepare_categorical_features()`.
Он предназначен для требований библиотеки, а не для статистического заполнения. При миграции бустингов
CatBoost будет представлять оставшийся пропуск допустимой строкой; LightGBM/XGBoost — использовать
собственный формат категорий/пропусков. В этом изменении стратегии и реализации бустингов не перенесены:
старый InputData-путь CatBoost с категориальным NaN по-прежнему не исправлен адаптером.

## Связанные исправления и совместимость

- Split срезает сохранённые категории вместе с остальными строковыми полями.
- Optional row deletion вычисляет маску для текущего predict batch, а не использует train mask;
  срезает target, idx и категории. Фильтрация столбцов обновляет mapping, имена и типы признаков.
- Merger упорядочивает каждую ветку по результирующему idx: прежняя маска оставляла исходный порядок строк.
  Сохранённые категории объединяются в том же порядке. Разным веткам выдаются независимые ID источников:
  одна ветка может заполнить пропуски, другая — оставить. Предсказания родителей-моделей являются числовыми
  признаками и не возвращают исходные категории. Схемы энкодеров перенумеровываются, decoder target сохраняется.
- Проекции сбрасывают категориальные значения и column mapping, поскольку исходных категориальных признаков
  в проекции уже нет; decoder target остаётся доступен.
- Категории участвуют в fingerprint и полном evaluation identity. Версия obligatory plan изменена, чтобы
  старые cache artifacts без сохранённых категорий не использовались как новые данные.
- Это затрагивает отмеченный ранее контракт выравнивания строк Industrial; синхронизация с внешним
  Industrial ещё понадобится. Внешний репозиторий не менялся.
- Старые глобальные InputData-энкодеры уже были удалены. Энкодеры-узлы оставлены: есть ссылки из каталогов,
  примеров и встроенного Industrial. Кроме того, старый OHE прокидывает параметры sklearn (например `drop`,
  `min_frequency`, `max_categories`), которых пока нет у TensorData encoder. Перед удалением нужно явно
  решить судьбу этих настроек, а не потерять их при чистке файлов.

## Файлы этой задачи

Данные и восстановление:

- `fedot/core/data/tensor_data/tensor_data.py` — два поля и `get_not_encoded_data()`.
- `fedot/core/data/tensor_data/contracts.py` — тип `CategoricalData`, согласованность sidecar и fitted encoding.
- `fedot/core/data/tensor_data/preparation.py` — сохранение значений/источников, fitted metadata и версия кэша.
- `fedot/core/data/tensor_data/tensor_data_creator.py` — передача сохранённых категорий в TensorData.
- `fedot/core/data/tensor_data/tools.py` — сравнение массивов строк и пропусков.
- `fedot/core/data/prepared_data/prepared_data.py` — перенос категорий и индексов между обработчиками.
- `fedot/core/data/split/data_split.py` — срез категориальных строк.
- `fedot/core/data/merge/data_merger.py` — выравнивание строк и категориальные метаданные веток.

Preprocessing и базовый контракт моделей:

- `fedot/preprocessing/methods/categorical_encoding.py` — кодирование константы обученным encoder, пустой OHE.
- `fedot/preprocessing/methods/imputation.py` — согласованная категориальная imputation и удаление строк batch.
- `fedot/preprocessing/methods/filtering.py` — сообщение о сохранённых колонках.
- `fedot/preprocessing/service/optional_service.py` — подключение обработчика и обновление метаданных.
- `fedot/preprocessing/tools/tools.py` — перенос sample-wise полей обратно в TensorData.
- `fedot/core/operations/implementations/base.py` — только hook подготовки категорий; прежние незакоммиченные
  изменения fit-stage методов в этом файле относятся к предыдущей задаче.
- `fedot/core/operations/implementations/data_operations/tools.py` — сброс категорий после проекций.

Кэш и проверки:

- `fedot/core/caching/fingerprints.py` — категории и вложенный fitted preprocessing handler в fingerprint.
- `fedot/core/caching/evaluation_context.py` — идентичность перенумерованных fitted encoders.
- `tests/preprocessing/test_categorical_preservation.py` — регрессии хранения, imputation, predict, кэша,
  неизвестных значений, выравнивания, нескольких энкодеров и decoder target.
- Этот документ и `docs/dev/fedot_tensordata_operations_migration_order_2026_11_07.md` — решения и пожелания.

Существующие изменения `strategies/data_operations/projection.py`, документа реструктуризации и
`tests/core/operations/test_fit_stage_contract.py` не принадлежат этой задаче.

- 111 адресных CPU-тестов: categorical preservation, optional preprocessing, column selection,
  TensorData contract/merge и hashing — прошли.
- После упрощения: 89 адресных тестов хранения категорий, optional preprocessing, контрактов TensorData
  и hashing прошли; добавлены проверки нормализации None/pd.NA и сохранения выбора моды при равных частотах.
- Короткий smoke на NVIDIA GeForce RTX 4080 SUPER: OHE и label, imputation/scaling, split/merge,
  совпадение CPU/CUDA — прошёл. Числовые features во время обработки остаются на CUDA.
- Полные поиск пайплайнов, нагрузочные сценарии и обучение бустингов в этой задаче не запускались.
