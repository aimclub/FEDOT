# FED-03: полный результат оценивания и управляемое воспроизводство

## Назначение

Этот срез продолжает FED-01 и FED-02. Он сохраняет `Pipeline`,
`PipelineObjectiveEvaluateWithTensorData.evaluate`, `ComposerBuilder` и оптимизатор
GOLEM, но уточняет договоренности между обучением, оценкой, кэшем и популяцией.
Зависимости от Industrial отсутствуют. GOLEM не изменяется.

До изменения ошибка второго разбиения прекращала цикл, после чего оценщик
возвращал среднее по первому успешному разбиению. Такой результат нельзя было
отличить от полной проверки. Очистка выполнялась только в конце успешного
разбиения. Кроме того, GOLEM мог самостоятельно повторить неудачную оценку.

Теперь успешным считается только результат, содержащий все разбиения. Решения
о повторах, полноте и уникальности описаны неизменяемыми значениями; обучение,
запись кэша и вызов операторов остаются в исполняющем слое.

## Публичные точки входа

| Задача | Точка входа |
| --- | --- |
| Совместимость с GOLEM | `PipelineObjectiveEvaluateWithTensorData.evaluate(graph) -> Fitness` |
| Подробный исход | `evaluate_result(graph) -> EvaluationOutcome` |
| Повторы | `RetryPolicy`, `RetryableEvaluationError` |
| Проверка кандидата | `PipelineValidator`, `ValidationResult` |
| Создание оценщика | `EvaluationRequest`, `EvaluatorFactory`, `EvaluationService` |
| Подключение к сборщику | `ComposerBuilder.with_evolution_hooks(EvolutionHooks(...))` |
| Уникальность популяции | `plan_unique_population`, `UniqueEvaluationDispatcher` |
| Воспроизводство | `ReproductionPolicy`, `BoundedReproduction`, `ReproductionReport` |
| Контекст кэша | `TensorDataCacheContext`, `tensor_data_identity` |

Реализации расположены в `fedot/core/optimisers/objective`,
`fedot/core/optimisers` и `fedot/core/caching`. `__init__.py` содержит лишь короткий
список публичных имен.

## Полнота и исходы

`EvaluationComplete` содержит ровно `expected_folds` записей `FoldRecord`
с последовательными номерами от нуля. Метрики должны быть конечными и иметь
одинаковую размерность. Среднее вычисляется только из полного набора.

`EvaluationIncomplete` содержит успешный префикс разбиений, журнал попыток и
`EvaluationFailure`. Средней метрики у этого типа нет. Метод `evaluate` преобразует
его в невалидный `Fitness`, который GOLEM не должен отбирать как успешного кандидата.
Ошибка очистки терминальна; исходная ошибка попытки при этом остается в журнале.

`EvaluationReused` ссылается на ранее завершенную оценку того же кандидата,
данных и настроек. Это не новая успешная попытка. Хранилище таких исходов
ограничено размером `result_cache_size`, по умолчанию 256. В нем нет моделей
или тензоров. `clear_results()` освобождает его; `GPComposer` вызывает этот метод
в `finally` после оптимизации.

Перед обучением оценщик полностью получает последовательность разбиений.
Поэтому ошибка самого источника не маскируется уже посчитанными метриками.
Если число разбиений известно заранее, следует передавать `expected_folds`:
это выявляет источник, который без исключения вернул укороченную последовательность.
Без этого аргумента число разбиений определяется фактическим результатом источника.

Готовую обученную модель можно оценить на одном явно заданном контрольном наборе.
Повторное использование такого состояния для нескольких разбиений запрещено:
иначе появляется утечка между разбиениями. Проверка не исправляет утечку,
допущенную при подготовке входных данных. Владелец источника обязан обучать
преобразования на обучающей части и передавать корректный `preparation_state`.

## Повторы и освобождение состояния

По умолчанию выполняется одна попытка. `max_attempts` включает первую попытку,
а не только дополнительные. Повтор разрешен лишь для `RetryableEvaluationError`
и, при явном указании `FailureKind.TIMEOUT`, для превышения времени.
Ошибки данных, проверки, метрик, обычного обучения, кэша и очистки не повторяются.

```python
from fedot.core.optimisers.objective.evaluation_contracts import (
    FailureKind, RetryPolicy,
)

policy = RetryPolicy(
    max_attempts=2,
    retryable=(FailureKind.TRANSIENT, FailureKind.TIMEOUT),
)
```

Для каждой начатой попытки `graph.unfit()` вызывается ровно один раз, в `finally`.
Исключение составляет сохраненная совместимость с `do_unfit=False`: только
последняя успешная модель передается во владение вызывающему коду. Все промежуточные
и неудачные попытки очищаются. В стандартном пути `GPComposer` этот режим не используется.

Предсказания сначала записываются в `PredictionCacheSession`. При неудаче локальные
записи отбрасываются; после успешной оценки и очистки они передаются общему кэшу.
Общий дисковый кэш принадлежит сборщику и не удаляется целиком при сбое одного
кандидата. Временные ссылки освобождаются, другие процессы не теряют свои записи.
Сохранение нескольких дисковых записей не является транзакцией всей попытки:
при ошибке ввода-вывода отдельные совместимые записи могут уже существовать.

`MetricsObjective.evaluate_strict` передает исключение метрики оценщику, чтобы тот
мог определить вид ошибки. Обычный `MetricsObjective.__call__` остается совместимым с GOLEM.
Сторонний `Objective`, который сам подавляет исключения, возвращает невалидную
метрику; восстановить скрытую причину и разрешить по ней повтор невозможно.

### Ограничение времени

Обучение с ограничением времени теперь работает с отдельной копией графа.
Состояние публикуется в исходный граф только при успехе. Поздний результат
фонового вычисления не может снова сделать исходный граф обученным после превышения
времени или записать предсказание в общий кэш. Рабочая копия и локальная сессия
кэша освобождаются в собственных блоках `finally`.

Это не обещание немедленно прервать произвольный нативный код: существующий
`func_timeout` использует поток. Если библиотека долго не возвращает управление
Python, ее память и вычисления могут сохраняться до выхода из вызова.
Для жесткого ограничения ресурсов нужен отдельный процесс или внешний исполнитель.
В этом срезе такой исполнитель не добавляется. Передаваемые пользовательские
модели должны поддерживать копирование, как и остальные модели `Pipeline`.

## Ключи и содержимое кэша

`TensorDataCacheContext.from_fold(train, test, fold_id, candidate_id)` учитывает:

- полное содержимое признаков, целевой переменной, предсказаний и индексов;
- семантические поля `TensorData`, а не только форму массивов;
- схему, план и снимки обученных обработчиков подготовки;
- номер разбиения, описание кандидата и вычислительное устройство;
- версию пространства ключей `namespace`.

`fingerprint` и `trace_uuid` исключены как производные служебные поля.
В отличие от быстрого исторического хеширования, строки признаков не выбираются
выборочно. При изменении кода внешних моделей или протокола эксперимента следует
изменять `cache_namespace`. Ключ не подменяет версию кода, которой управляет владелец
эксперимента.

```python
from fedot.core.caching.cacher import Cacher
from fedot.core.caching.evaluation_context import TensorDataCacheContext

context = TensorDataCacheContext.from_fold(train, test, 0, pipeline.descriptive_id)
cache = Cacher()
cache.cache_tensor_data(prepared, input_data=train, operation=plan, context=context)
loaded = cache.load_tensor_data(train, plan, context=context)
```

Вызовы `Cacher` без `context` сохраняют старое поведение. Контекстные записи не
пересекаются со старым пространством ключей. Загрузка контекстной записи проверяет
полное содержимое; неверный или поврежденный артефакт не принимается за попадание
в кэш. Состояния `fit` и `predict` разделены. Артефакты остаются доверенными
локальными файлами: эта проверка не превращает pickle в безопасный формат обмена.

Кэш обученных операций и кэш предсказаний получают полный ключ разбиения вместо
одного целого номера. Старые методы остаются пригодными для других потребителей.

## Популяция и граница GOLEM

`ContractEvaluationDispatcher` использует публичные методы GOLEM для оценки
кандидата и применения результатов. Он не выполняет скрытый дополнительный
запуск, когда вся популяция не прошла оценку или истекло время. Также отключена
вторая очистка того же графа со стороны GOLEM: ее уже выполняет оценщик FEDOT.
`UniqueEvaluationDispatcher` устраняет структурные дубли до передачи работ
потокам или процессам, в том числе в начальной популяции.
Если среди дублей уже есть успешно оцененный экземпляр, он сохраняется независимо
от своего положения в списке. Неоцененный экземпляр не может вытеснить готовый
результат и вызвать лишний запуск.
В рабочий процесс передается явный снимок регистраций FED-02. Каждый вызов
получает отдельную область `extension_scope`, которая закрывается и при ошибке.
Повторно используемый процесс не сохраняет регистрации предыдущего запуска.

`BoundedReproduction` подключается явно через `ReproductionPolicy`. Он использует
существующие операции отбора, скрещивания и мутации GOLEM, а не второй оптимизатор.
Результат учитывается один раз по исходному описанию кандидата. Связь с результатом
исполнителя проверяется по `uid`: обучение может нормализовать параметры узлов.
Неудачный кандидат не запускается вновь в том же цикле воспроизводства, обходя
ограничение числа попыток оценщика.

```python
from fedot.core.optimisers.evaluation_hooks import EvolutionHooks
from fedot.core.optimisers.population import ReproductionPolicy

hooks = EvolutionHooks(
    retry_policy=policy,
    expected_folds=3,
    cache_namespace='experiment-v2',
    reproduction=ReproductionPolicy(seed=42, max_attempts=8, required_valid_ratio=1.0),
)
composer = builder.with_evolution_hooks(hooks).build()
```

Чистая функция `plan_reproduction` выводит seed попытки из seed запуска,
номера поколения и номера попытки. Для одинаковых входов получается одинаковый
план. Адаптер сохраняет и восстанавливает состояния генераторов Python и NumPy
вокруг операций GOLEM. Обучение выполняется за пределами этого участка.
Входные графы не изменяются: операторы получают принадлежащие попытке копии.
Эта гарантия относится к решениям воспроизводства, а не к побитовой повторяемости
CUDA, сторонних моделей или нестандартных операторов со своими источниками случайности.

В текущем GOLEM нет отдельного метода подключения фабрики исполнителя и
воспроизводителя. FEDOT использует его существующие публичные атрибуты
`eval_dispatcher` и `reproducer`, проверяя поддерживаемый тип.
Частные методы GOLEM не переопределяются. Для стороннего оптимизатора нужен
собственный адаптер; он не заменяется автоматически. Стабильная фабрика этих
компонентов в будущем API GOLEM устранит этот небольшой разрыв.

## Проверки

- Сбой второго разбиения после успешного первого возвращает неполный исход.
- Повторяемая ошибка допускает ровно заданное число попыток; обычные ошибки не повторяются.
- Проверены ошибки метрики, неконечные значения, изменение размерности и сбой очистки.
- Повторный кандидат использует прежний исход; измененные данные его не используют.
- Проверены успешное и неуспешное сохранение временного кэша, полное восстановление
  `TensorData` и состояния подготовки, поврежденное содержимое, разделение контекстов.
- Проверены позднее завершение ограниченного по времени обучения и очистка рабочей копии.
- Проверки Hypothesis охватывают полноту усреднения, конечность повторов,
  устойчивый порядок уникальных кандидатов и детерминированность планов.
- Реальное CPU-обучение и сборка `ComposerBuilder` с оптимизатором GOLEM проверены
  на небольшом наборе без внешних данных.

Основная команда проверки:

```text
python -m pytest tests/core/optimisers tests/core/caching tests/core/pipelines/test_timed_fit_ownership.py tests/core/pipelines/tuning/test_tuner_builder.py -q
```

Для проверок свойств нужен Hypothesis. Он объявлен в дополнительной группе
зависимостей `test` (`pip install .[test]`); TensorData также требует установленный
PyTorch. В ходе этой реализации зависимости не устанавливались.

Проверка 21 сентября 2026 года в предоставленном окружении Python 3.11:
целевой набор вместе с `tests/extensions` и независимыми инвариантными проверками
дал **353 passed, 2 skipped**.
Пропуски относятся к существующим проверкам кэширования. Проверены настоящие
рабочие процессы на CPU, передача расширений и повторное использование процессов.
`compileall` и `git diff --check` выполнены без ошибок.

Широкая проверка дала **1131 passed, 12 failed, 6 skipped**. Это те же 12 ошибок,
которые воспроизводились до FED-03. Среди них: старые тестовые подмены API без `use_optional_preprocessing`,
передача NumPy-массивов в метрики для TensorData, устаревшие ожидания настроек
и сетевой тест загрузчика UCR. Этот результат не заменяет повторную общую проверку
после устранения долгов миграции. Существующие задания CI запускают `test/unit`
и `test/integration`; целевой набор выше находится в `tests` и должен запускаться
отдельно при проверке этого среза.

Локальный Python 3.10.0 выполнил **333** проверки этого набора; 12 проверок свойств
завершились внутри Hypothesis с `AttributeError` для `TreeNode.is_exhausted`.
Причина — ошибка `dataclasses(slots=True)` в Python 3.10.0, исправленная
в последующих исправляющих выпусках Python 3.10. Падение воспроизводится на
минимальном объекте Hypothesis до вызова кода FEDOT. Поэтому для проверки Python
3.10 нужен актуальный исправляющий выпуск, а не Python 3.10.0.

Полный набор `tests` содержит отдельные старые ошибки миграции API и тест загрузки
UCR из сети. Их нельзя объявлять успешными на основании целевого прогона FED-03.
Новые тесты не используют сеть, GPU или скачиваемые датасеты.
