# Вопросы для экспериментов с моделями FEDOT

10 ноября 2026. Пополняемый список решений, которые требуют проверки на реальных данных.
Исправление явных ошибок и перенос на TensorData сами по себе не являются основанием менять defaults.

## Бустинги: eval set и early stopping

- [ ] Сравнить обучение на всех train-строках без внутренней валидации и текущий split 80/20.
  Включить маленькие наборы (около 200 строк), ligands и более крупные табличные данные;
  качество оценивать на одинаковом внешнем test/CV, использовать несколько seed.
- [ ] При одинаковом внутреннем split сравнить отключённый early stopping, несколько значений patience
  и очень большую patience. Записывать число выполненных раундов, best iteration, число сохранённых /
  используемых деревьев, время и внешнюю метрику. Большая patience не отключает best-iteration selection.
- [ ] Для CatBoost отдельно сравнить `use_best_model=True/False` при одинаковом early stopping.
  Для LightGBM/XGBoost явно зафиксировать, какие итерации участвуют в predict.
- [ ] Сравнить сохранение модели на части train и повторное обучение на всех train-строках с выбранным
  числом итераций. Контролировать общий бюджет и отсутствие доступа к внешнему test при выборе итерации.
- [ ] По результатам решить, нужен ли порог размера данных для eval split, и пересмотреть долю split,
  patience и политику финального refit. До экспериментов текущую политику не менять.
- [ ] На одинаковых настройках сравнить прямой вызов библиотеки, predefined model и запуск AutoML с ней
  в initial assumption. Разделить влияние настроек, поиска, тюнинга и финального fit; фиксировать timeout.

Наблюдение пользователя: на ligands отличие сохранялось даже при patience=1e9. Механизм воспроизведён
на LightGBM 4.6.0: обучение выполнило все 24 раунда, но итоговый booster сохранил лучшую первую итерацию.
Это объясняет возможное отличие, но не заменяет повторение конкретных ligands-экспериментов.

## Табличные преобразования: унаследованные политики

- [ ] Оценить необходимость nan_to_num(..., 0) после scaling/normalization/poly_features: это неявное
  заполнение пропусков, существовавшее до миграции. Отдельно проверить OHE с NaN, влияние на модели,
  умеющие missing values, и согласовать отличие от explicit optional imputation. Пока поведение сохранено.
- [ ] Оценить ограничение polynomial features десятью случайно выбранными исходными столбцами на CPU/GPU;
  сравнить качество, память и время с другими бюджетами. При текущем переносе cap не изменён.


### RFE на кодированных категориях (11 ноября)

Сравнить поколоночный legacy RFE на OHE с отбором целых source groups. Сейчас политика сохранена:
RFE может удалить часть dummy columns, а enable_categorical восстанавливает исходную категорию целиком,
если у неё осталась хотя бы одна колонка. Поэтому выбранное представление зависит от следующей модели.
Не менять группировку в рамках контейнерной миграции; оценить качество и бюджеты отдельно. Также отдельно
оценить GPU linear RFE: другие solver coefficients могут менять mask даже при близких предсказаниях.


### Фильтры и балансировка (11 ноября)

- [ ] Решить семантику balance_ratio=0: старый runtime делал full balance, хотя docstring обещал no-op.
  При миграции сохранён runtime; отдельно проверить и согласовать исправление публичного параметра.
- [ ] Оценить class sampling/качество после перехода NumPy RNG → Torch RNG. Механика sklearn resample
  сохранена и проверена при одинаковых draws; одинаковые seeds разных библиотек не дают тех же строк.
  CPU/CUDA Torch sequences также не обещаны одинаковыми. Оценивать несколько seeds и class sizes.
- [ ] При GPU IsolationForest/cuML или отдельном GPU RANSAC сравнить не только fit speed, но inlier masks,
  class retention guard и downstream quality. Текущие sklearn алгоритмы/retention defaults не менялись.


### Цели decompose и probability vocabulary (11 ноября)

- [ ] Сравнить цели ensemble внутри residual fork: прежний локальный residual target, исходный target
  и другие осмысленные конструкции. Это изменение алгоритма графа, не контейнерной миграции;
  сейчас сохраняется legacy main priority / shallowest auxiliary fallback.
- [ ] При переносе target coding проверять координаты argwhere: legacy binary decompose ошибочно
  индексировал таблицу парами (row,column) по оси строк и всегда делал первую метку positive.
  Исправление обсуждено и сохранено; следующий регрессор проверен на signed targets [-0.2,0.8].
- [ ] Для decompose при фильтрации классов до первоначального fit согласовать получение полного
  fitted class order от producer. Текущий vocabulary сохраняется при fit самого decomposer и не
  сужается на последующих subsets; несовпадение первоначальных осей выдаёт явную ошибку.


### Единый каталог CPU/GPU (11 ноября)

- [ ] Согласовать пространства тюнинга с выбранным исполнением. CatBoost GPU не принимает rsm/
  colsample_bylevel для обычных classification/regression objectives, border_count ограничен сильнее;
  max_leaves зависит также от grow_policy. Не скрывать это удалением заданных параметров в адаптере.
  Аналогично проверить общие пространства sklearn/cuML и библиотечные ограничения GPU.
  Небольшое исправление уже сделано: cuML KNN получает metric=minkowski, чтобы p=1 не игнорировался.
- [ ] Сравнить RF sklearn/cuML на одинаковых данных/параметрах и нескольких seeds: в обновлённом примере
  make_moons(n_samples=1000, noise=0.1, random_state=137), split seed=137 получены roc_auc_pen около
  0.999 CPU и 0.931 CUDA. Это одиночный smoke, не оценка общего качества; причину различия ещё не установили.
  Проверить library defaults, разбиения/квантили, критерий, ограничения и feature sampling до предпочтений.
- [ ] Отдельно проверить multi-GPU, CUDA_VISIBLE_DEVICES и соответствие OpenCL gpu_device_id устройству
  CUDA у LightGBM. На одной RTX 4080 SUPER device_type=gpu работает, CUDA-enabled build отсутствует.
  Не считать GPU fit гарантией GPU inference: сохранить штатное поведение библиотеки и измерять обе стадии.
