# Improved automatic text detection in FEDOT

## Задача

Исследовать текущий механизм автоматического определения текстовых колонок
в FEDOT и подход, предложенный в PR #903

Цель - уменьшить количество ложных определений строковых признаков
как естественного текста

## Текущий FEDOT

Текущая реализация в основном использует:

- строковый тип данных
- проверку совместимости с числами
- долю уникальных значений > 095

Из-за этого уникальные строковые признаки могут ошибочно определяться как text:

- имена
- URL
- идентификаторы
- email
- UUID
- пути к файлам

## PR #903

В PR #903 были предложены:

- порог unique ratio = 06
- проверка размера TF-IDF словаря
- отдельное обнаружение URL

Эксперименты показали, что подход лучше текущей реализации,
но большой словарь сам по себе не гарантирует наличие естественного текста

Например, уникальные имена, идентификаторы и названия товаров
также могут иметь большой TF-IDF vocabulary

## Предложенный подход

В ImprovedTextDataDetector используются характеристики всей колонки:

- длина строк
- количество слов
- доля уникальных значений
- размер и структура словаря
- доля букв и цифр
- доля пунктуации
- URL ratio
- email ratio
- UUID ratio
- path ratio
- ID ratio
- повторяемость токенов
- повторяемость структурных шаблонов

Сначала исключаются явно структурированные данные,
после чего оцениваются признаки естественного текста

## Эксперимент

Сравниваются:

1. Current FEDOT
2. PR #903
3. ImprovedTextDataDetector

Метрики:

- Precision
- Recall
- F1

Текущие синтетические эксперименты используются только для проверки
гипотез и не рассматриваются как окончательная оценка качества
